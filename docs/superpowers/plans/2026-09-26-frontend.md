# Workflow dashboard implementation plan

**Goal:** A professional Next.js dashboard showing the actual 311 backend workflow and an honest normal-response versus memory-response evaluation.

**Spec:** `docs/implementation-plan.md` and the four conversation endpoints merged into main at e498862.

**Design:** Light neutral workspace, persistent navigation, indigo workflow accents and green memory accents. React owns interactive state and small SVG graph geometry. Summary cards lead into the pipeline, bounded memory graph, response comparison and source/trace inspection. Mobile uses horizontal navigation and stacked panels. View selection is URL-backed. Source IDs remain visible and inspectable; node/edge placement is schematic. No generated quality score or causal recurrence claim.

**Integration:** A typed server-only client calls the PR endpoints. A Node route calls OpenRouter with the same model, settings, prompt and bounded history for both responses, adds retrieved context only to the memory call, then stores both responses. Environment credentials stay server-side. The initial bundled snapshot comes from the existing deterministic Python harness and is labeled recorded demo. Live graph views represent the retrieved subgraph, not the full persistent store. Stale results remain visible with an explicit error on failed requests.
